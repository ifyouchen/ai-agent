# 墨枢 InkAxis 写改编一体化产品方案

版本：V1.0  
日期：2026-06-20  
交付类型：Markdown 产品方案  
产品定位：AI 小说创作、小说改写、小说转短剧分场稿的一体化创作平台

## 1. 背景与结论

墨枢 InkAxis 当前项目已经具备 AI 对话、知识库、流式生成、RAG、审计、Token 统计等基础能力。`小说skill/` 中沉淀了写长篇、写短篇、拆文、审查、去 AI 味、封面、扫榜等完整网文创作方法论，可以作为产品流程、提示词策略、质量检查规则和样例库使用。

本方案建议将小说能力设计为一个独立的「创作中心」，以“写小说 -> 改小说 -> 小说转短剧分场稿”为核心闭环。第一版不直接导入 `小说skill/` 中的 Hook、Agent 和脚本，而是先把能力产品化，沉淀为稳定页面、流程、任务、数据对象和 AI 链路。`小说skill/` 的完整能力迁移清单见《小说skill能力迁移清单.md》，后续可以删除原目录，避免污染当前项目。

核心结论：

- 可行性高：现有项目的 LLM、SSE、RAG、文档上传、任务审计和 Token 统计能力可以复用。
- MVP 应聚焦“写改编闭环”：先完成作品创建、章节编辑、改写对照、短剧分场稿生成、质量检查与导出。
- 短剧脚本标准采用“短剧分场稿”，不是传统电影剧本，也不是完整拍摄分镜稿。
- `改编-上岸 (1).docx` 可作为小说改编方案与题材迁移样例，`剧本 (1).docx` 可作为短剧分场稿初稿样例，但需要通过平台标准补齐格式与质检项。
- `小说skill/` 中 13 个 skill、7 个 Agent、Hook、规则、参考资料和采集脚本全部纳入产品蓝图，按 V1/V1.5/V2/V3 分期实现。

## 2. 产品定位

墨枢 InkAxis 的创作中心面向网文作者、短剧编剧和内容工作室，帮助用户把一个故事从想法推进到小说正文，再从小说正文改写为更适合短剧表达的分场脚本。

产品价值：

- 对网文作者：降低开书、续写、改稿、审稿成本。
- 对短剧编剧：快速从小说或故事文本中拆出分集、场次、冲突、钩子和对白。
- 对内容工作室：建立统一的故事资产库、脚本版本管理和改编生产流程。

一句话定位：

> 墨枢 InkAxis 是一个面向网文与短剧生产的 AI 创作工作台，让作者从写小说、改小说到生成可编辑短剧分场稿都在同一个项目里完成。

## 3. 用户角色

### 3.1 网文作者

目标：

- 快速开书，生成设定、大纲、章节。
- 保持人物、剧情和世界观一致。
- 提升爽点、节奏、对白和商业化表达。

核心需求：

- 长篇/短篇创作模板。
- 章节续写、扩写、缩写、改风格。
- 人设一致性与剧情漏洞检查。
- 去 AI 味与平台化语言优化。

### 3.2 短剧编剧

目标：

- 将小说、短篇故事或改编方案转换为短剧分场稿。
- 快速拆分集数、场次、冲突和钩子。
- 控制对白口语化和可拍性。

核心需求：

- 从章节或 DOCX 导入文本。
- 自动提取故事核、人物关系和冲突线。
- 自动生成分集大纲与分场脚本。
- 输出短剧质检报告与导出文件。

### 3.3 内容工作室

目标：

- 批量管理小说项目、改编项目和脚本草稿。
- 统一审查标准、版本与导出格式。
- 追踪 AI 成本和生产效率。

核心需求：

- 作品库与项目分组。
- 多版本管理、协作批注、任务进度。
- 质量评分、导出记录、Token 统计。

## 4. MVP 范围

### 4.1 包含范围

MVP 需要完成五个核心能力：

1. 作品库：创建小说项目、导入文本/DOCX、管理章节与脚本草稿。
2. 写小说：生成设定、大纲、章节正文，支持续写和章节审查。
3. 改小说：按片段、章节、整卷进行改写，提供三栏对照确认。
4. 转短剧：从小说内容生成改编方案、分集大纲和短剧分场稿。
5. 质量检查与导出：检查短剧格式、节奏、冲突、钩子和小说残留，导出 Markdown/DOCX。

### 4.2 暂不包含范围

第一版暂不做，但已经纳入全量产品路线：

- 外部平台扫榜与浏览器自动采集。
- 小说封面生成。
- 长篇/短篇完整拆文库。
- 多 Agent 对抗式审查。
- 项目模板、规则中心、AI 角色配置中心。
- 完整拍摄分镜稿、镜号、机位、景别等重制作能力。
- 多人实时协同编辑。
- 复杂版权合同、交易、发行管理。

### 4.3 成功标准

MVP 上线后需要满足：

- 用户可以创建一个小说项目并生成至少一章正文。
- 用户可以对章节进行改写，并逐段接受或拒绝 AI 结果。
- 用户可以选择若干章节生成短剧分集大纲。
- 用户可以生成符合短剧分场稿结构的脚本。
- 用户可以看到质量检查报告，并导出 Markdown 或 DOCX。

## 6. 核心业务流程

### 6.1 写小说流程

```text
创建作品 -> 选择类型 -> 生成设定 -> 生成人物 -> 生成大纲 -> 生成章节 -> 人工编辑 -> 审查 -> 保存版本
```

关键规则：

- 长篇项目默认强调世界观、人物关系、主线/支线、章节连续性。
- 短篇项目默认强调故事核、情绪拉扯、反转、爆点和结尾余味。
- 每次 AI 生成都保存为草稿版本，不直接覆盖用户正文。
- 章节审查包含剧情漏洞、人设一致性、节奏拖沓、AI 味、爽点不足等维度。

### 6.2 改小说流程

```text
选择文本范围 -> 选择改写模式 -> AI 诊断问题 -> 生成改写稿 -> 三栏对照 -> 用户逐段确认 -> 保存版本
```

改写范围：

- 片段：适合局部润色和对白优化。
- 章节：适合节奏、爽点和结构优化。
- 整卷：适合题材迁移、人设重构、风格统一。

改写模式：

- 基础润色：修正病句、重复、表达不顺。
- 去 AI 味：减少模板化语气、过度总结和机械转折。
- 爽点增强：强化压迫、反击、揭露、打脸和情绪释放。
- 节奏压缩：删掉低信息密度段落，提高剧情推进速度。
- 情绪强化：增强羞辱、委屈、误会、愤怒、心动、爽感。
- 对白口语化：把书面表达改为更自然的角色对话。
- 题材迁移：如现代故事迁移为古代科举、豪门、职场、悬疑等设定。

三栏对照：

```text
左栏：原文
中栏：AI 改写稿
右栏：修改说明、问题诊断、可选动作
```

用户动作：

- 接受本段。
- 拒绝本段。
- 再改一次。
- 指定要求再改。
- 查看差异。
- 回退到上一个版本。

### 6.3 小说转短剧流程

```text
选择小说内容 -> 提取故事核 -> 生成改编方案 -> 拆分集数 -> 生成分集大纲 -> 生成分场稿 -> 质量检查 -> 人工编辑 -> 导出
```

输入来源：

- 当前作品章节。
- 粘贴文本。
- DOCX 文档。
- 已有改编方案。

输出结果：

- 改编策略说明。
- 人物改编表。
- 情节取舍表。
- 分集大纲。
- 短剧分场稿。
- 质量检查报告。
- Markdown/DOCX 导出文件。

## 7. 功能模块设计

### 7.1 作品库

作品库统一管理小说项目、改编项目和脚本草稿。

项目卡片字段：

- 作品名称。
- 类型：长篇、短篇、改编、短剧脚本。
- 当前状态：构思中、写作中、改写中、改编中、已导出。
- 最近编辑时间。
- 当前字数、章节数、集数、场次数。
- 关联知识库。

主要操作：

- 新建作品。
- 导入文本/DOCX。
- 继续写作。
- 继续改编。
- 查看版本。
- 导出归档。

### 7.2 写小说

写小说模块由开书向导、设定管理、人物管理、大纲管理、章节编辑器组成。

开书向导字段：

- 作品类型：长篇/短篇。
- 目标平台：通用、番茄、起点、晋江、知乎盐选、短篇故事。
- 题材类型：都市、古言、现言、玄幻、悬疑、重生、追妻、虐渣等。
- 主角设定。
- 核心冲突。
- 情绪卖点。
- 目标字数。

章节编辑器 AI 操作：

- 续写。
- 扩写。
- 缩写。
- 改风格。
- 强化冲突。
- 对白优化。
- 去 AI 味。
- 章节审查。
- 查一致性。

### 7.3 改小说

改小说模块服务于存量文本优化和题材迁移。

任务配置：

- 改写范围。
- 改写模式。
- 保留项：人物关系、关键剧情、叙事视角、结局、平台风格。
- 强化项：爽点、反转、冲突、对白、情绪、节奏。
- 禁止项：改变核心设定、增加新主角、改变结局、使用敏感表达。

结果展示：

- 原文与改写稿段落对齐。
- 高亮新增、删除、改动。
- AI 标注每段修改原因。
- 支持逐段确认。

版本策略：

- 每次发起改写前自动创建快照。
- 用户确认后的内容生成新版本。
- 支持查看版本列表和回退。

### 7.4 小说转短剧

转短剧模块是 MVP 的核心出口。

改编策略：

- 保留原故事核。
- 强化短剧开场钩子。
- 压缩低戏剧性情节。
- 将心理活动外化为动作、对白、道具或场面。
- 将小说叙述改为可拍画面。
- 每集结尾设置追看钩子。

分集策略：

- 默认 1 到 3 分钟一集。
- 每集只解决一个核心冲突或推进一个关键误会。
- 前三集承担强钩子、人物关系、核心矛盾建立。
- 中段保持冲突升级与反转。
- 末段集中揭露、反击、情绪释放和结局。

场次策略：

- 每场必须有明确场景、人物、本场功能和冲突推进。
- 场次不承担纯说明任务。
- 对白优先服务于冲突、人物关系和信息揭露。
- 旁白只补必要信息，不能替代表演和画面。

### 7.5 质量检查

质量检查维度：

- 格式完整度。
- 前 3 秒钩子。
- 冲突密度。
- 结尾钩子。
- 对白口语化。
- 小说残留。
- 心理活动外化。
- 人物动机清晰度。
- 可拍性。
- 平台感。

质量报告输出：

```text
总评分：
主要问题：
逐集问题：
逐场问题：
可直接修复项：
需要人工判断项：
建议改写提示词：
```

## 8. 短剧分场稿标准

默认格式：

```text
第N集
预计时长：
核心爽点：
本集冲突：
结尾钩子：

【第N场】
场景：内/外｜地点｜日/夜
人物：
本场功能：
预计时长：

画面：
旁白：
对白：
表演/镜头：
钩子：
```

字段说明：

- 预计时长：帮助控制短剧节奏。
- 核心爽点：本集观众最想看的情绪回报。
- 本集冲突：本集推动的主要矛盾。
- 结尾钩子：促使用户继续观看的悬念、反转或情绪断点。
- 画面：可拍摄的动作、场景、人物状态。
- 旁白：少量补充信息，不替代剧情演绎。
- 对白：角色台词，强调口语化和冲突感。
- 表演/镜头：必要的表演提示、镜头方向，不进入完整分镜复杂度。
- 钩子：本场末尾的小悬念、小反转或情绪推进。

## 9. 样例文档使用方式

### 9.1 `改编-上岸 (1).docx`

定位：

- 作为“小说改编方案”和“题材迁移”的参考样例。
- 展示如何把现代故事迁移为古代科举语境。
- 用于验证平台能否识别原始故事、改编目标、人物映射和情节取舍。

产品使用方式：

- 导入后进入“改编方案识别”流程。
- AI 生成故事核、人物映射、冲突迁移、短剧化建议。
- 用户确认后再生成分集大纲和短剧分场稿。

### 9.2 `剧本 (1).docx`

定位：

- 作为短剧分场稿初稿样例。
- 不是严格传统影视剧本。
- 可用于测试短剧格式识别、字段补齐和质量检查。

产品使用方式：

- 导入后识别已有场次、对白、动作和旁白。
- 自动补齐集数、预计时长、核心爽点、本集冲突、结尾钩子。
- 标记小说残留、旁白过多、冲突不足、钩子缺失等问题。

## 12. AI 链路设计

### 12.1 写小说链路

```text
用户输入 -> 题材识别 -> 商业卖点提取 -> 设定生成 -> 人物生成 -> 大纲生成 -> 章节生成 -> 一致性审查 -> 保存草稿
```


- 创建作品数。

## 14. 风险与对策

### 14.1 AI 输出不可控

风险：剧情跑偏、人物关系错乱、脚本格式不稳定。  
对策：引入结构化输出、阶段生成、质量检查、格式修复和人工确认。

### 14.2 长文本上下文不足

风险：长篇小说转短剧时模型遗忘前文。  
对策：先做故事核、人物表、情节节点和章节摘要，再分批生成分集与场次。

### 14.3 改写覆盖原稿

风险：用户误操作导致原文丢失。  
对策：所有改写先进入对照确认，接受后生成新版本，支持回退。

### 14.4 短剧脚本不够可拍

风险：生成内容仍像小说，无法拍摄。  
对策：质量检查中强制标记心理活动、抽象描写、长旁白和不可拍内容。

### 14.5 成本过高

风险：长篇生成和改编消耗大量 Token。  
对策：任务前估算 Token，支持范围选择、分阶段生成和失败续跑。
