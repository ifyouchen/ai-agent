1. 产品概述

1.1 产品定位

墨枢（InkAxis） 是一款专为长篇创作者打造的一站式智能创作平台。以 "小说转剧本" 为核心差异化功能，辅助 "可控长篇续写" 与 "分级智能润色"，打通从灵感到影视化改编的完整创作流。

一句话价值主张：让网文作者 10 分钟拿到可用于拍摄的剧本初稿，让编剧从手动改编中解放。

1.2 核心差异化

维度墨枢现有竞品
长篇一致性上下文锚点系统，锁定角色/道具无记忆或简单向量检索
剧本改编专业心理外化策略 + 行业格式导出简单对话提取，无格式
创作流整合写-改-编一站式，无需跨工具功能割裂
文风定制用户上传作品学习专属风格仅预设模板

1.3 产品目标

  • V1.0：验证"小说转剧本"PMF，50%内测用户可直接使用生成剧本
  • V1.1：形成"写-改-编"最小闭环，完成完整用户链路
  • V2.0：通过版本快照、角色图谱、文风市场建立资产壁垒

2. 市场分析与竞品

2.1 市场机会

  • 网文市场规模：2025年中国网络文学市场规模超 400 亿元，作者群体超 2000 万
  • 短剧市场爆发：2025年短剧市场规模达 500 亿元，大量剧本需求
  • 影视改编需求：每年数百部网文出售影视版权，但专业改编人才稀缺
  • AI写作渗透率：约 30% 的网文作者尝试过 AI 辅助，但专业工具缺失

2.2 竞品矩阵

产品写作润色剧本转换长处弱点

2.3 竞争壁垒

  1. 技术壁垒：剧本改编 Prompt 链 + 锚点记忆系统
  2. 数据壁垒：用户作品数据 → 个人文风模型
  3. 社区壁垒：作者角色库、世界观模板沉淀

3. 用户画像与场景

3.1 核心用户画像

画像A：网文大神/腰部作者

  • 年龄：25-35岁 · 特征：有完本作品，月收入 5000-50000
  • 痛点：作品售出影视版权但不会写剧本；长篇人设管理困难
  • 需求：一键剧本转换 + 一致性检查

画像B：短剧编剧

  • 年龄：22-30岁 · 特征：MCN/短剧公司签约，日产 3-5 集
  • 痛点：从网文/IP 中提炼剧本效率低；手动改格式耗时
  • 需求：快速转化 + 标准格式导出

画像C：新人作者

  • 年龄：18-28岁 · 特征：正在创作第一部作品，卡文频发
  • 痛点：不知如何推进剧情；人设经常矛盾
  • 需求：智能续写 + 设定管理

3.2 核心场景

场景用户动作系统响应
灵感起步输入"废柴少年捡到魔剑复仇"自动生成章纲 + 角色小传 + 世界观

4. 核心功能详细设计

4.1 项目管理

作品层级：

Project（项目） ├── title, genre, summary, world_setting ├── Volume（卷） │ ├── title, order, summary │ ├── Chapter（章节） │ │ ├── title, content, status, word_count │ │ ├── outline（大纲节点） │ │ ├── script_version（关联剧本） │ │ └── ChapterSnapshot（版本快照） │ └── ... └── ...

新建作品流程：

  1. 输入书名 + 一句话简介 + 题材标签
  2. AI 生成可选世界观设定集（3-5 条）
  3. 用户确认/修改后进入写作界面

4.2 AI 写小说

4.2.1 骨架式生成

用户输入：一句话梗概 ↓ AI 输出：卷-章大纲树（可拖拽调整） ↓ 用户确认大纲 ↓ 逐章生成正文

大纲生成 Prompt 要点：输入梗概 + 题材标签 → 输出 3-5 卷，每卷 10-15 章，每章 1 句话情节提要，用户可增删改、拖拽排序。

4.2.2 分段续写

交互流程：用户定位到章节末尾或指定位置 → 点击"续写" → AI 根据锚点包生成 800-2000 字 → 流式输出 → 用户可选：接受 / 重写 / 从 3 个分支中选。

4.2.3 互动卡点

触发条件：生成到剧情关键决策点、对话出现明确选择问句、章节结尾处。

4.3.1 选中即操作

4.4.1 功能入口

  • 命令面板：Cmd+K → 输入"改编"
  • 支持选择：全卷改编 / 选中章节改编

4.4.3 心理外化策略选择器

当检测到心理描写时，右侧面板展示多种外化方案（动作外化、对白外化、独白保留、跳过），用户可按需选择或一键应用推荐策略。

支持格式：中文影视标准格式、好莱坞 Final Draft (.fdx)、简单分镜表（含景别/运镜建议）。

5. 小说转剧本 Prompt 链设计

5.1 整体架构

小说原文 ↓ [Step 1] 文本预处理 → 清洗无关内容 ↓ [Step 2] 段落分类器 → 标注类型(动作/对白/心理/叙述) ↓ [Step 3] 场景分割器 → 识别场次边界 ↓ [Step 4] 逐场改编器 → 心理外化 + 剧本生成 ↓ [Step 5] 格式组装器 → 补全+格式化+导出 ↓ 最终剧本

5.2 Step 1: 文本预处理

清洗规则：删除作者有话说、作者注、求票求收藏等非正文内容；删除广告、推广链接；保留所有正文段落、对白、描写；不改变任何正文文字；保留章节标题。

5.3 Step 2: 段落分类器

类型定义：scene_heading_implied（隐含场景）、action（动作/场景描写）、dialogue（对话）、internal（心理活动）、narration（叙述性过渡）。输出严格 JSON 格式。

5.4 Step 3: 场景分割器

场次切换规则（满足任一即切场）：地点发生实质变化、时间发生较大跳跃、隐含的新场景头、明确转场词、闪回/回忆段落单独成场。输出包含场景号、场景头、段落索引的 JSON。

5.5 Step 4: 逐场改编器

包含心理外化子步骤（4种策略：动作外化、对白外化、独白保留、直接删除）和剧本片段生成（标准中文剧本格式，现在时态，可视化描写）。

5.6 Step 5: 格式组装器

补全缺失场景头、修正重复或跳跃的场号、合并连续同场景场次、检查角色名一致性、在剧本开头加上标题页。

5.7 完整调用流程

def novel_to_script(novel_text, user_strategy_choices=None):
    """
    小说转剧本完整Pipeline
    
    Args:
        novel_text: 小说原文
        user_strategy_choices: {segment_index: "A"/"B"/"C"/"D"} 
                               用户的外化策略选择
    Returns:
        final_script: 完整剧本
    """
    # Step 1: 预处理
    cleaned_text = llm_call(
        system="preprocess_prompt",
        input=novel_text,
        temperature=0.1
    )
    
    # Step 2: 段落分类
    classified = llm_call(
        system="classify_prompt",
        input=cleaned_text,
        temperature=0.1,
        response_format="json"
    )
    # JSON容错
    classified = validate_and_retry(classified, expected_schema="segments")
    
    # Step 3: 场景分割
    scenes = llm_call(
        system="scene_split_prompt",
        input=json.dumps(classified),
        temperature=0.2,
        response_format="json"
    )
    scenes = validate_and_retry(scenes, expected_schema="scenes")
    
    # Step 4: 逐场改编
    script_scenes = []
    for scene in scenes["scenes"]:
        # 4a: 提取心理活动段落
        internal_segments = [
            seg for seg in classified["segments"] 
            if seg["index"] in scene["segments"] and seg["type"] == "internal"
        ]
        
        # 4b: 对每个心理描写获取外化方案
        externalization_map = {}
        for seg in internal_segments:
            ext = llm_call(
                system="externalize_prompt",
                input=json.dumps({"segment_index": seg["index"], "content": seg["content"]}),
                temperature=0.5,
                response_format="json"
            )
            externalization_map[seg["index"]] = ext
        
        # 4c: 应用用户选择（或默认推荐）
        strategy_map = {}
        for seg_idx, ext in externalization_map.items():
            if user_strategy_choices and seg_idx in user_strategy_choices:
                strategy_map[seg_idx] = user_strategy_choices[seg_idx]
            else:
                strategy_map[seg_idx] = ext["options"]["recommended"]
        
        # 4d: 生成剧本片段
        scene_text = assemble_scene_text(scene, classified)
        script_fragment = llm_call(
            system="adapt_scene_prompt",
            input=json.dumps({
                "scene_text": scene_text,
                "strategy_map": strategy_map,
                "heading": scene["heading"]
            }),
            temperature=0.6,
            stream=True  # 流式输出
        )
        script_scenes.append({
            "scene_number": scene["scene_number"],
            "content": script_fragment
        })
    
    # Step 5: 格式组装
    final_script = llm_call(
        system="format_assemble_prompt",
        input=json.dumps(script_scenes),
        temperature=0.2
    )
    
    return final_script

6. 上下文锚点技术方案

6.1 问题定义

核心矛盾：大模型上下文窗口有限（128K-200K tokens），网文动辄百万字（远超窗口），不塞设定 → AI 失忆 → 角色矛盾。

锚点系统目标：每次 AI 调用时，动态组装一个"最小必要上下文包"，用最小 Token 成本换取最大一致性。

6.2 整体架构

6.4 锚点生命周期管理

初始化（首章提取）：从输入的小说文本中提取所有角色、关键道具、世界观设定。

增量更新（每章写完后）：提取新章节中的变化，处理角色更新、新角色创建，检测潜在矛盾并通知用户。

用户锁定机制：用户可在角色库/道具库中手动开启锁定，锁定后 AI 在任何情况下不可修改该锚点的属性。

6.5 上下文动态组装引擎

def assemble_context(chapter_id, task_type, project_id):
    """
    为每次LLM调用组装最小必要上下文包
    """
    context = {}
    
    # === 第1层：基础信息（始终包含） ===
    context["task_instruction"] = get_task_prompt(task_type)
    context["story_summary"] = get_project_summary(project_id)  # 500字全书概要
    context["chapter_outline"] = get_chapter_outline(chapter_id)
    context["preceding_text"] = get_preceding_text(chapter_id, chars=1000)
    
    # === 第2层：近期事件摘要 ===
    context["recent_summary"] = get_recent_chapters_summary(
        chapter_id,
        num_chapters=5,
        max_tokens=800
    )
    
    # === 第3层：相关锚点检索 ===
    outline_text = context["chapter_outline"] + " " + context["preceding_text"]
    
    # 3a: 关键词匹配（精确、快速）
    mentioned_chars = keyword_match(
        outline_text,
        get_all_characters(project_id),
        match_fields=["name", "aliases", "abilities.name"]
    )
    mentioned_items = keyword_match(
        outline_text,
        get_all_items(project_id),
        match_fields=["name", "aliases"]
    )
    
    # 3b: 语义检索（补充隐含关联）
    semantic_chars = vector_search(
        outline_text,
        character_event_embeddings,
        top_k=3
    )
    semantic_items = vector_search(
        outline_text,
        item_event_embeddings,
        top_k=3
    )
    
    # 3c: 合并去重，锁定态优先
    all_mentioned_chars = deduplicate_and_merge(
        mentioned_chars + semantic_chars,
        prioritize_locked=True
    )
    all_mentioned_items = deduplicate_and_merge(
        mentioned_items + semantic_items,
        prioritize_locked=True
    )
    
    # 3d: 角色关系扩展（1度关联）
    expanded_chars = expand_relationships(
        all_mentioned_chars,
        depth=1,
        max_additional=3
    )
    
    # === 第4层：Token预算分配 ===
    token_budget = get_token_budget(task_type)
    anchor_budget = token_budget - sum_token_usage(context, exclude="anchors")
    
    scored_anchors = score_anchor_importance(
        all_mentioned_chars + all_mentioned_items,
        outline_text
    )
    
    context["anchors"] = allocate_tokens_by_score(
        scored_anchors,
        budget=anchor_budget
    )
    
    # === 第5层：世界观设定（全部注入，通常很少） ===
    context["world_settings"] = get_locked_world_settings(project_id)
    
    return context

6.6 重要性评分算法

def score_anchor_importance(anchors, current_context_text):
    """
    对锚点进行重要性评分，用于Token预算分配
    """
    for anchor in anchors:
        score = 0.0
        
        # 1. 关键词匹配分数 (0-30)
        keyword_count = count_keyword_occurrences(
            anchor["name"], current_context_text
        )
        score += min(keyword_count * 10, 30)
        
        # 2. 语义相关分数 (0-20)
        semantic_score = cosine_similarity(
            embed(anchor["name"] + " " + str(anchor["attributes"])),
            embed(current_context_text)
        )
        score += semantic_score * 20
        
        # 3. 锁定状态加分 (0-20)
        if anchor["locked"]:
            score += 20
        
        # 4. 最近活跃度 (0-15)
        chapters_since_last = get_chapters_since_last_appearance(anchor)
        score += max(15 - chapters_since_last, 0)
        
        # 5. 关系网络中心度 (0-15)
        centrality = calculate_relationship_centrality(anchor)
        score += centrality * 15
        
        anchor["importance_score"] = score
    
    return sorted(anchors, key=lambda x: x["importance_score"], reverse=True)

12. 合规与伦理

12.1 版权与免责

用户协议核心条款：

  • 用户内容所有权：用户拥有其输入和生成内容的所有权
  • 平台使用权：平台可使用用户内容优化模型（可关闭）
  • AI 生成声明：导出剧本自动添加"本作品部分由 AI 辅助生成"水印或标注
  • 禁止生成内容：明确禁止生成违法违规、侵权、色情内容

版权风险规避：不提供"模仿特定作者风格"的功能；文风学习仅基于用户自己上传的作品；查重功能仅为辅助，不做版权判定。

12.2 内容安全

多层过滤机制：输入过滤（实时敏感词检测）→ 输出过滤（流式敏感词替换/阻断）→ 后审核（举报系统 + 抽检机制）。

12.3 数据隐私

作品默认私有，仅作者可见；分享链接加密，24小时失效；用户可随时导出全部数据；账号注销后 30 天内彻底删除数据。
